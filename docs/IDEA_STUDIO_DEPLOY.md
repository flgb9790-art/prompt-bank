# Студия идей: запуск и проверка

Реализована первая версия. Эти инструкции не означают, что deployment или платная
генерация уже выполнены. Производственная база при разработке не изменялась.

## Возможности

- `/studio` на сайте; в Mini App: Профиль → Студия идей. Доступ только для
  подписанного Telegram-пользователя из `ADMIN_TELEGRAM_IDS`.
- 1–10 самостоятельных идей с промптом и изображением в подборке, либо
  переработка вставленного исходного промпта. Названия — 2–3 слова на выбранном языке.
- Поиск вдохновения через OpenAI Web Search; ссылки берутся из фактических
  результатов поиска. Источники относятся ко всей подборке, не являются утверждением
  об авторстве или популярности отдельных идей. Готовые промпты не копируются.
- Учёт последних 150 черновиков и 100 опубликованных материалов: проверка названий,
  сходства текста и повторов сочетания темы/стиля. Это эвристика, не гарантия
  семантической уникальности; окончательный отбор остаётся за администратором.
- Редактирование, выбор, отклонение, отдельная переработка текста и повтор изображения.
  Изменение промпта помечает прежнее изображение как неактуальное.
- «Персонаж и темы»: фото персонажа, название, пожелания к образам, главная тема
  (по умолчанию роскошная жизнь) и дополнительные направления. Сезон, регион,
  полушарие и поводы ближайших 45 дней фиксируются на дату генерации подборки.
- Публичный промпт собирается из проработанных блоков одежды и аксессуаров,
  образа, позы/выражения, сцены, света, камеры/композиции и текстур. Он сохраняет
  внешность любого приложенного референса, без личного имени, фиксированного
  цвета глаз/волос, возраста, пропорций кадра или разрешения. Формат и разрешение
  остаются параметрами генератора, не частью публикуемого промпта.
- При наличии фото используется `POST /v1/images/edits` с реальными байтами
  референса, иначе — `images/generations` с иллюстративным персонажем.
  Отсутствующий файл закреплённого референса не подменяется новым лицом.
- Подтверждение выбранных материалов → создание записей библиотеки → существующий
  Telegram-обработчик → сохранение точных ссылок. Pinterest вызывается отдельно,
  после переключения подключения в production и подтверждения каждого пина.
- Все задания сохраняются в PostgreSQL. Закрытие браузера не останавливает работу.
  На нескольких backend-экземплярах одновременно работает один обработчик студии
  с возобновляемой арендой в БД. Перезапуск сохраняет готовые результаты, но не
  повторяет прерванные платные запросы автоматически.

## Переменные backend Railway

```env
OPENAI_API_KEY=<секретный ключ проекта OpenAI>
STUDIO_TEXT_MODEL=gpt-5-mini
STUDIO_IMAGE_MODEL=gpt-image-2.5-flare
STUDIO_IMAGE_QUALITY=low
STUDIO_DAILY_IMAGE_LIMIT=10
STUDIO_DAILY_TEXT_LIMIT=12
```

Ключ добавлять только в backend → Variables. Не добавлять его в Git, чат, браузер,
miniapp или переменные `VITE_*`. Доступность модели зависит от аккаунта; для
генерации изображений может требоваться верификация организации OpenAI.
`STUDIO_IMAGE_QUALITY=medium` включает более высокое качество; по умолчанию
используется low для первых подборок. Цены и лимиты доступа проверять в OpenAI.

Лимиты считают попытки, включая ошибки, и сбрасываются в 00:00 UTC. Веб-поиск и
создание текстов — отдельные запросы. Приложение не гарантирует денежный потолок:
настройте бюджет/уведомления в проекте OpenAI. Неудачный или прерванный вызов может
быть оплачен. Автоматических сетевых повторов OpenAI нет.

Для файлов необходим настроенный storage: Railway Volume с `UPLOADS_DIR` либо
существующий Supabase Storage. `MEDIA_PUBLIC_URL` должен открывать сохранённые
картинки извне: Telegram и Pinterest загружают эти медиа. Публичный каталог не
содержит черновики; изображения используют существующее публичное хранилище медиа.

## Миграция и сборка

Перед изменением production сохраните резервную копию PostgreSQL. Аддитивный патч
создаёт только пять новых таблиц, индексы и внешние ключи; существующие промпты
не переписываются. Повторное применение проверено на PGlite.

Из backend с переменными нужной базы:

```powershell
cd D:\prompt-bank-main\repository\backend
npm run prisma:patch-idea-studio
npm run prisma:patch-studio-character
npm run build
npm run test:studio
npm run test:security
npm run test:publications
cd ..\miniapp
npm run build
```

Не используйте исторические SQLite migrations или `migrate reset`. Старт backend
по-прежнему выполняет `prisma db push --skip-generate`; не добавляйте
`--accept-data-loss`. Обновите backend и miniapp вместе после проверки кода.
Push в `main` запускает настроенные автодеплои Railway.

## Первый реальный запуск

Проверка повторов сравнивает сцену и действие из разделов «Сцена» и «Поза и
выражение» (или английских аналогов). Общие инструкции о внешности, одежда,
свет, обработка, одинаковый стиль или короткое название не блокируют разные
сюжеты. Для старых неструктурированных промптов удаляется вводный абзац о
референсе. Полная история используется локально, в ИИ передаётся компактное
описание содержательной части. Если часть идей повторяется, сохраняются новые,
число изображений и прогресс уменьшаются, а в подборке показывается предупреждение.
Если повторяется всё, новые изображения не создаются. Платных автоматических
повторов текстового запроса нет.

Поиск ограничивает сводку 450 словами, но выделяет 10 000 токенов с учётом
внутреннего рассуждения. Если поиск уже вернул источники, но исчерпал длину ответа,
генерация использует только названия и ссылки с предупреждением в подборке,
без обрезанной сводки и дополнительного платного поискового запроса. Незавершённые
JSON-промпты и ответы, остановленные фильтром, не принимаются. Причины обрыва и
счётчики токенов записываются в журнал без текста запросов, фото и секретов.

1. Войти администратором, открыть студию. Убедиться, что ключ распознан; сам ключ
   в интерфейсе и API не возвращается.
2. Выбрать одну идею, темы и язык. Запустить вручную после просмотра окна с
   количеством платных генераций. Проверить реальную картинку и качество текста.
3. После изменения текста сохранить его и сгенерировать актуальное изображение.
4. Отметить нужные материалы и проверить предпросмотр. Нажать подтверждение
   публикации только для тех материалов, которые действительно следует отправить.
5. Проверить пост и сохранённую ссылку. Если отправка прервалась, сначала проверить
   канал: при существующем посте сохранить URL в карточке библиотеки. Только если
   поста действительно нет, нажать «Проверил: поста нет» для разрешения повтора.
6. После проверки модели, качества и затрат можно включить ежедневную генерацию
   и сохранить настройки. По умолчанию: 10 идей, 09:00, Europe/Minsk, язык English.
   Если сервер был выключен в указанное время, сегодняшняя подборка запускается
   после включения; пропущенные прошлые дни не оплачиваются. Дневная подборка
   не повторяется автоматически после ошибки. Ручная генерация тоже расходует
   общий дневной лимит.

История в интерфейсе показывает последние 30 подборок и 15 задач; более старые
данные не удаляются. Неподтверждённые материалы никогда не публикуются по расписанию.

## Фото персонажа

Перед загрузкой в генератор backend локально на CPU находит лицо и глаза,
выравнивает линию глаз и кадрирует область лица с волосами. Генератор получает
подготовленный портрет, а не позу тела и всю сцену из исходного фото. Сам исходник
не меняется. Приватный кэш `*.identity-v1.jpg` хранится рядом с оригиналом;
превью с `?view=identity` доступно только администратору. Повторы старых подборок
используют их исходный ключ, но тоже подготавливают лицо. Если лицо или оба глаза
не найдены, новая подборка не ставится в платную очередь.

Локальная модель MediaPipe и её веса включены в `backend/models/face-detection`;
в production эта папка должна попасть в образ вместе с `dist`. Дополнительных
AI-запросов нет, сетевой загрузки модели во время работы нет. Предобработка
устраняет боковой наклон, но не восстанавливает невидимые детали профиля и не
гарантирует точность ракурса у генеративной модели.

На странице студии откройте «Персонаж и темы», загрузите чёткое фото лица JPG,
PNG или WebP до 10 МБ / 30 мегапикселей. Backend проверяет декодируемость файла,
убирает метаданные и сохраняет нормализованный JPEG в приватной папке
`UPLOADS_DIR/.studio-references`. Эта папка закрыта публичным middleware; превью
доступно только через API с подписанным входом администратора. Не размещайте её
в обход приложения на общедоступном CDN. Railway Volume должен сохраняться.

Фото передаётся только генератору изображения OpenAI. В веб-поиск не передаются
ни фото, ни название/описание персонажа. В Telegram/Pinterest публикуется результат,
а не исходный референс. Сама подборка сохраняет снимок профиля и ключ своего фото:
замена или удаление фото из текущего профиля действует на следующие подборки.
Старые референсы сохраняются приватно для повторов; полное удаление требует
удаления связей/данных соответствующих подборок администратором.

Референс задаёт только внешность и видимый возраст. Генератор получает отдельное
указание заново поставить сцену, изменить позу, поворот/наклон головы, взгляд и
мимику по тексту, не копировать геометрию исходного фото и не состаривать человека.
Новые подборки получают разные задания на позу и ракурс для каждой идеи; при
переработке сцена следует пожеланиям администратора. Обновлённые правила действуют
и при ручном повторе изображения старого черновика; старые картинки автоматически
не перерисовываются и платные вызовы не запускаются.

Правки публичного текста делают изображение неактуальным. Перед публикацией
нужно сгенерировать актуальное превью и визуально проверить лицо, одежду и сцену.
Точное совпадение результатов разных генераторов не гарантируется.

## Локальная визуальная проверка без ключа

```powershell
cd D:\prompt-bank-main\repository\miniapp
npm exec vite -- --host 127.0.0.1 --port 4317 --strictPort
```

Открыть `http://127.0.0.1:4317/qa/studio.html`. Это отдельная dev-страница с
синтетическими данными и SVG-заглушками. Все вызовы генерации и публикации
подменены, в production-сборку эта HTML-точка входа не включается.
