# Pinterest: назначение — конкретный Telegram-пост

## Изменения

В `Prompt` добавлены nullable-поля `telegramMessageId`, `telegramChatId`, `telegramPostUrl`.
После успешной отправки они сохраняются транзакцией вместе со статусом Telegram-публикации.
Короткий полный текст помещается в подпись первого элемента альбома; длинный отправляется
отдельными текстовыми сообщениями. Ссылка указывает на первое сообщение с текстом промпта,
а не на последнее вложение. Текст не обрезается; части длиннее 4000 UTF-16 единиц разбиваются
без разрыва emoji. Для канала с username используется `https://t.me/username/messageId`,
иначе `https://t.me/c/channelId/messageId` (доступ только участникам канала).

Pinterest использует только `Prompt.telegramPostUrl`. Общая ссылка канала, устаревший
`pinterestLink` клиента и `destinationLink` старой Pinterest-публикации не заменяют её.
ID пина и `https://www.pinterest.com/pin/{id}/` продолжают сохраняться отдельно.

При создании с двумя флажками сервер сначала отправляет Telegram и сохраняет ссылку,
затем создаёт запись Pinterest со статусом `awaiting_confirmation`, без вызова Pinterest API.
Оба клиента показывают адрес в подтверждении и вызывают Pinterest отдельно.
Запрос публикации Pinterest должен содержать `destinationLink`, совпадающий с сохранённым
адресом; при несовпадении требуется новое подтверждение. При ошибке Telegram пин не создаётся.
Повтор Pinterest не вызывает Telegram. Отмена подтверждения оставляет промпт и адрес
сохранёнными; продолжить можно из карточки.

## Развёртывание

При разработке реальные сообщения и пины не создавались. SQL проверен на изолированном
PostgreSQL (PGlite), включая повторное применение и сохранность существующей строки.
После отдельного разрешения пользователя SQL-патч применён к production 18 октября 2026:
все три столбца проверены, количество промптов до и после обновления — 106.
Перед применением сохранён локальный снимок данных всех таблиц в игнорируемой папке `backups/`.

1. Сделайте резервную копию рабочей PostgreSQL-базы. Сначала проверьте обновление на staging.
2. В окружении backend с настроенными `DATABASE_URL` и `DIRECT_URL` выполните из каталога backend:

   ```powershell
   npm ci
   npm run prisma:patch-telegram-post
   npm run build
   ```

   Команда добавляет три nullable TEXT-столбца в `Prompt`, транзакционно и с `IF NOT EXISTS`.
   Никакие материалы и старые публикации не обновляются и не отправляются.
   **Не запускайте `prisma migrate deploy`, `migrate reset` или `migrate dev` на рабочей базе:**
   существующая история `prisma/migrations` относится к SQLite, текущая схема — PostgreSQL.
   Используйте именно добавленный SQL-патч. Штатный `prisma db push` в start-скрипте остаётся
   без изменений, но не заменяет предварительную проверку схемы и миграции.
3. Выполните локальные проверки (публикации и БД в тестах подменены):

   ```powershell
   npm run test:publications
   ```

4. В каталоге miniapp выполните `npm ci` и `npm run build`.
5. После отдельного разрешения на публикацию кода разверните backend `prompt-bank` и miniapp
   `diplomatic-communication` в Railway-проекте `exemplary-emotion`, окружение `production`.
   Сначала примените SQL и обновите backend, затем miniapp. Учтите: push в `main` ранее
   автоматически запускал Railway-деплои обоих сервисов; для контролируемого порядка временно
   отключите автодеплой в настройках Railway или используйте отдельную ветку.
6. Проверьте `/api/health` и администраторскую карточку промпта. На staging проверьте:
   Telegram + Pinterest → точный адрес → подтверждение; ошибка Telegram → отсутствие пина;
   ошибка Pinterest → повтор без Telegram; «Открыть Pin» → Pinterest.

## Существующие материалы

Откройте карточку под администратором, вставьте ссылку вида `https://t.me/channel/123`
в поле «Ссылка на Telegram-пост» и нажмите «Сохранить ссылку». Для этого используется
`PATCH /api/admin/prompts/:id/telegram-post-link` с JSON `{ "telegramPostUrl": "..." }`.
Материал в канал не отправляется. Проверьте показанное назначение и создайте пин.
Ссылка на сам канал или приглашение отклоняются сервером и формой.
Содержание и доступность вручную указанного поста администратор проверяет самостоятельно:
приложение проверяет формат адреса, но не читает историю канала.

Существующие пины не редактируются. Новая ссылка применяется к будущим публикациям.
Автоматического backfill нет: сохранённый ранее ID мог относиться только к анонсу.

Форматы ссылок соответствуют [документации Telegram](https://core.telegram.org/api/links#message-links).
